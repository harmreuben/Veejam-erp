# Database schema

Source of truth: `prisma/schema.prisma`. Changes are made only through migrations in `prisma/migrations/`, never by hand in the Supabase dashboard.

## Conventions

- Postgres on Supabase. Table and column names are `snake_case` (`@@map`/`@map`); Prisma models are `PascalCase`.
- Primary keys: `uuid` generated by Postgres (`gen_random_uuid()`); logs and staging rows use `bigserial`.
- Money: `Decimal(18,2)`. Rates and percentages: `Decimal(9,4)`. Never floating point.
- Quantities: integers in base units (pieces).
- Timestamps: `timestamptz(3)`, stored in UTC, shown in Africa/Nairobi.
- Posted financial rows are never updated or deleted; corrections are new rows.
- Foreign keys use `ON DELETE RESTRICT`, except staging rows, which belong to their batch.
- **Row-level security is enabled on every table with no policies.** Supabase's Data API (the publishable and anon keys) therefore can't read or write anything; only the server, connecting through Prisma, can. A test fails if a new table forgets this.

## Phase 2 tables

| Table                   | Purpose                                                                               | Key rules                                                                                                                  |
| ----------------------- | ------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `users`                 | ERP users, linked to Supabase Auth by `auth_user_id`                                  | Unique auth id and email; email stored lowercase; deactivated users must have `deactivated_at`                             |
| `company_settings`      | Company profile shown on documents                                                    | Exactly one row (`id = 1`); `version` for edit-conflict detection; currency is 3 capital letters; payment terms 0–365 days |
| `document_sequences`    | Next number per document type (INV-, QUO-, SO-, RCT-, CN-, DN-, PO-, GRN-, ADJ-, JE-) | `next_number ≥ 1`; incremented under a row lock inside the posting transaction (Phase 4)                                   |
| `audit_log`             | Who did what, when, before/after                                                      | **Append-only**: a trigger rejects UPDATE, DELETE and TRUNCATE. Secrets are redacted before writing                        |
| `legacy_import_batches` | One staged CSV export from the old system                                             | Unique per file name + SHA-256, so the same file can't be staged twice                                                     |
| `legacy_rows`           | Each CSV row, stored unchanged as JSON                                                | Row numbers match the spreadsheet (header is row 1)                                                                        |

Rules Prisma can't express (check constraints, the audit trigger, RLS) are hand-written at the end of `prisma/migrations/20261021090000_init/migration.sql`.

## Roles

Fixed roles in the `UserRole` enum: `OWNER`, `ADMIN`, `ACCOUNTANT`, `SALES`, `STOREKEEPER`. What each may do is defined in code (`src/server/auth/permissions.ts`) and checked on the server for every action. The system always keeps at least one active owner; this is enforced with a row lock, so two owners acting at the same moment can't both be removed.

## Planned entities by phase

**Phase 3 — master data and stock:** `Product`, `Sku` (code, barcode, unit, `unitsPerPack`, `packsPerCarton`, cost, prices, tax code, reorder level, status), `PriceList`, `PriceListItem`, `Customer`, `CustomerType`, `Supplier`, `Warehouse`, `StockBalance`, `StockMovement` (ledger), `Batch`, `StockCount`, `StockCountLine`, `ImportJob`, `ImportJobRow`, and the legacy import that turns staged rows into these records.

**Phase 4 — sales:** `Quotation`, `SalesOrder`, `StockReservation`, `Invoice` (including historical invoices imported from the old system, with their original `VJL-` numbers), `DeliveryNote`, `DocumentShareLink`.

**Phase 5 — money:** `PaymentMethod`, `Payment`, `PaymentAllocation`, `Receipt`, `CreditNote`, `SalesReturn`, `TaxCode`, `Account`, `JournalEntry`, `JournalLine`, `AccountingPeriod`, `PurchaseOrder`, `GoodsReceipt`, `SupplierInvoice`.

**Phases 6–7 — WhatsApp:** `WhatsAppMessage`, `WhatsAppEvent` (unique event id for idempotency), `PendingConfirmation`.

## Checking the database matches the schema

```powershell
npm run db:status   # are all migrations applied?
npm run db:drift    # does the live database match schema.prisma? (exit code 0 = yes)
```
